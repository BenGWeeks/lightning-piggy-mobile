= Choosing a swap backend

Account → On-chain → Swap server URL configures the Boltz-compatible server
used for new Bitcoin mainnet ↔ Lightning swaps on this device, across accounts.
No swap server is selected by default. Without one, swap-based Send, Move,
and Receive explain how to configure a server; new swaps cannot start.
Direct sends from an on-chain hot wallet do not require a swap server.

Enter an HTTPS server URL (for example `https://swaps.example.com`) or its v2
API base (`https://swaps.example.com/v2`). Reverse-proxy prefixes and explicit
ports are supported, for example `https://swaps.example.com:8443/boltz/v2`.
Select *Check and save*. The app checks both BTC/BTC swap-pair endpoints before
saving; this checks basic API compatibility, not the operator's trustworthiness,
liquidity, or full swap execution. Failures leave the saved setting unchanged.
*Clear swap server URL* clears the draft; *Check and save* saves the empty
selection without a network request. Existing swaps keep their original server.

The endpoint must be a Boltz swap backend, not Bitcoin RPC, LND, or a Boltz client.
This setting does not change the app's Bitcoin network or Electrum server.
HTTP, embedded credentials, query parameters, fragments, and WebSocket URLs are
rejected. HTTPS requires a certificate trusted by the phone; TLS verification is
not disabled for private servers. There is no automatic fallback to another
provider when the chosen backend is unavailable.

== Move from a watch-only wallet to Lightning

In Move, a watch-only on-chain source is labelled *Pay from your other wallet*.
Choose a Lightning destination and enter the amount that it should receive.
The quote includes Boltz's fee; your external wallet adds its own network fee.
*Create payment request* creates an unpaid submarine swap and destination invoice.
Lightning Piggy never signs or broadcasts a payment from the watch-only wallet.

Pay the exact on-chain amount shown, from the wallet that holds the keys (for
example a hardware wallet or Sparrow). The QR and copied payment URI contain
that exact amount, including Boltz's fee. Copy address and copy sats amount are
also available. Do not pay an expired request or pay the same request twice.
The timeout is a Bitcoin block height, not a guaranteed wall-clock deadline.

Closing Move leaves app-level settlement tracking running. Reopen Move with the
same source/destination to resume the funding instructions, including after a
restart. The Lightning wallet's existing swap transaction row and completion
notification show settlement. Earlier requests remain available in the swap
history inside Move. A failed funded swap keeps its private recovery material;
claim a refund into your own wallet using those details with compatible swap
refund tooling after the timeout block. The *Copy private refund details* action
exports those keys deliberately; keep the details private. A normal wallet
payment cannot reverse the lockup transaction. Unfunded expired requests have
nothing to refund. Existing hot-wallet swaps retain their normal refund flow.

Run `.maestro/payments/flow-154-watch-only-swap-to-lightning.yaml` on the test
Piggy emulator with the flow-114 Watch Wallet 1 fixture and a connected Lightning

== Private family server

Connect each phone to your existing WireGuard VPN before checking or using a
private backend. Its HTTPS hostname must resolve and be reachable through the
VPN. Allow the swap API only on the VPN interface and keep node RPC, LND admin,
and database ports private. No additional public API port is needed.

This change does not deploy a backend, provision certificates, configure a VPN,
or add server authentication headers. Per-user daily swap counts, total sats,
and concurrency limits must be enforced by the backend/access layer with an
identity per family member; app-only limits cannot protect the server.

== Existing swaps and recovery

Before a newly created swap can be returned to a caller for funding, the app
persists its originating API URL in SecureStore under `boltz_backend_<swapId>`.
WebSocket subscriptions, HTTP polling, transaction details, reverse recovery,
and submarine refund lookups use that record rather than the current setting.
The WebSocket address is derived from the same API base with `wss:` and `/ws`.

The provider record is retained after completion for transaction history.
Swaps created before this feature have no provider record and continue to use
the original public Boltz endpoint, even after selecting a private server.
Storage read errors fail the lookup rather than switching providers. Reused
swap IDs with an existing provider or pending recovery record are rejected
before callers can overwrite another swap's recovery secrets.

Keep these provider records together with the existing swap recovery records;
changing the setting cannot transfer an already-created swap to another server.

== Manual verification

. Open On-chain settings and confirm the server field is empty on a fresh install.
. Open Send with a BIP21 address and amount: the missing-server message is shown
  and Send is disabled. Do not send funds during this check.
. Enter an invalid URL, HTTP URL, or incompatible HTTPS endpoint: saving fails.
. Connect WireGuard, enter a compatible private HTTPS endpoint, and save.
. Restart the app and confirm the setting persists.
. In a controlled test environment, create swaps in both directions and confirm
  server logs show fee, creation, status, and refund lookups at that server.
. With a pending swap, change the default server and restart. Recovery and
  transaction details must continue querying the original provider.
. Disconnect WireGuard: the private server becomes unreachable without any
  fallback requests to the public provider.

== Public endpoint status (2026-10-11)

Boltz's https://api.docs.boltz.exchange/[API documentation] and
https://github.com/BoltzExchange/boltz-web-app/blob/main/src/configs/mainnet.ts[mainnet configuration]
still name `https://api.boltz.exchange`; the latter also sets `swapsSuspended: true`.
Both `api.boltz.exchange` and `boltz.exchange` returned NXDOMAIN in the checks
for #1169 (including Google public DNS). Neither the documented endpoint nor
`https://boltz.exchange/api` could be verified as a working public replacement.
The app therefore has no default for new swaps. The legacy endpoint remains
only for existing, unpinned swaps; it is not a fallback for new ones.

Send requires a completed quote and a known wallet balance covering the
recipient amount plus the quoted fees. A changed wallet, destination, amount,
or sheet session invalidates the displayed quote. Server-side preflight still
checks the approved swap quote before creating or paying a swap.
