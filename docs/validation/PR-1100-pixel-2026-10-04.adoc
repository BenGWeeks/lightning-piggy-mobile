= PR #1100: Physical Android payment notification check

Tested on 4 October 2026 using a physical Pixel 8 running GrapheneOS
2026100201. The Preview build includes the Android background-payment PR,
its native-host resume recovery fix (3a99444a), and the configurable swap
backend PR. Background monitoring, notification permission and unrestricted
battery use were enabled.

A mainnet LND wallet sent a one-sat payment to a separate Coinos wallet.
The payment settled with a one-sat routing fee. With Preview removed from
Recents, Android reported zero Preview recent tasks while the persistent
foreground service continued running. Before sending, Android's keyguard
reported `showing=true`, `inputRestricted=true`, and the screen was off.

Without reopening Preview, Android posted a new `payments` notification:

* Title: `Payment received`
* Body: `Open Lightning Piggy for details`
* Importance: `HIGH`

The generic body verifies the app's enabled lock-screen content privacy
setting. Repeated notification inspection found one payment notification,
not another copy on subsequent history polls. A separate earlier payment
also produced a notification while another app was foregrounded.

Do Not Disturb was enabled on the test phone. Android reported that it
intercepted the notification and suppressed visual effects; this test proves
notification posting, not an audible alert or an unrestricted heads-up alert.
The phone's Do Not Disturb preference was not changed for this check.

== Automated validation

The full suite passed: 185 suites and 2,123 tests. Focused watcher tests
passed: 102 tests. The native-host recovery regression fails on the previous
implementation and passes with the fix; a stop during startup still prevents
polling from being resurrected. TypeScript and ESLint reported no errors.

== Remaining device checks

This check does not establish reboot/first-unlock recovery, prolonged Doze
latency, network/VPN recovery, message delivery, or all account-switch and
wallet-removal permutations. Those remain separate acceptance checks.
Android Force stop prevents execution until the app is reopened.

No NWC credential, invoice, recovery phrase, transaction hash, private service
URL or private network address is included in this evidence.
