= Supported Standards
:toc:

This document lists the Bitcoin, Lightning, and Nostr standards implemented by Lightning Piggy Mobile.

== BIPs (Bitcoin Improvement Proposals)

[cols="1,3,4"]
|===
| Standard | Name | Usage

| https://github.com/bitcoin/bips/blob/master/bip-0021.mediawiki[BIP-21]
| URI Scheme
| Parsing and generating `bitcoin:` URIs with optional `?amount=` parameter for QR codes (SendSheet, ReceiveSheet)

| https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki[BIP-32]
| Hierarchical Deterministic Wallets
| xpub key derivation for watch-only wallets; claim keypair generation for Boltz swaps (`onchainService`, `boltzService`)

| https://github.com/bitcoin/bips/blob/master/bip-0039.mediawiki[BIP-39]
| Mnemonic Seed Phrases
| 12/24-word mnemonic validation and import for hot wallets; normalization and whitespace handling (`WalletContext`)

| https://github.com/bitcoin/bips/blob/master/bip-0084.mediawiki[BIP-84]
| Native SegWit HD Wallets
| Derivation path `m/84'/0'/0'` for `bc1q...` address generation; zpub/ypub to xpub conversion (`onchainService`)

| https://github.com/bitcoin/bips/blob/master/bip-0327.mediawiki[BIP-327]
| MuSig2 Schnorr Key Aggregation
| Taproot internal key aggregation (Boltz pubkey + app claim pubkey) for Boltz v2 swap claims (`boltzService`)

| https://github.com/bitcoin/bips/blob/master/bip-0340.mediawiki[BIP-340]
| Schnorr Signatures
| Taproot script-path signing for Boltz swap claim transactions (`boltzService`)

| https://github.com/bitcoin/bips/blob/master/bip-0341.mediawiki[BIP-341]
| Taproot (SegWit v1)
| Taproot output key tweaking, leaf hash computation, control block construction, and script-path spending for Boltz claims (`boltzService`)
|===

== Marmot Protocol (MLS over Nostr) — Alpha

https://github.com/marmot-protocol/marmot[Marmot] carries MLS (https://www.rfc-editor.org/rfc/rfc9420[RFC 9420]) group messaging over Nostr. Lightning Piggy implements it with `@internet-privacy/marmot-ts` and is wire-compatible with White Noise.

Status against the https://github.com/marmot-protocol/marmot/blob/master/mip-coverage.md[Marmot MIPs]:

[cols="1,2,4"]
|===
| MIP | Name | Status in Lightning Piggy

| MIP-00
| Credentials & Key Packages
| Implemented. Kind-30443 key packages, one `d` slot per install, refreshed weekly, retired on sign-out (`marmotSession`, `marmotKeyPackageLifecycle`); managed under Account → Messages → Invitation keys

| MIP-01
| Group Construction & Group Data
| Implemented: name and `admin_pubkeys` (shown and managed; only admins rename or change members). Commits realign the extension order for White Noise (`marmotProposals`)

| MIP-02
| Welcome Events
| Implemented. Kind 444, NIP-59 gift-wrapped; joined only from people you follow (`marmotWelcomeRouter`)

| MIP-03
| Group Messages
| Implemented. Kind-445 group events; text, reactions (1:1), edits, "delete for everyone", member removal (`marmotSession`, `marmotEdits`, `marmotDeletions`)

| MIP-04
| Encrypted Media (`encrypted-media-v2`)
| Implemented. Photos and voice notes: ChaCha20-Poly1305 blobs on Blossom, key derived from the MLS epoch secret; v1 still read (`marmotMedia`)

| MIP-05
| Push Notifications (`marmot-push-v1`, draft)
| Implemented. Kind-446 triggers to other members' notification servers (found via each server's kind-10050), and an opt-in receive side per account (`marmotPush`, `marmotPushNotifier`, `marmotPushRegistrar`)

| MIP-06
| Multi-device (being redesigned upstream)
| Partial: an invite adds all of a contact's fresh devices in one commit (`marmotInvitees`); an existing 1:1 later adds devices either person installed since, from their published key packages (`marmotDmDeviceSync`, #1559). No device linking or pairing
|===

See `PROTOCOLS.adoc` → "Marmot (MLS over Nostr)" for the event kinds.

== Boltz Exchange Protocol

The app uses https://docs.boltz.exchange[Boltz v2 API] for trustless cross-chain transfers:

- **Reverse submarine swaps** (Lightning -> on-chain): Pay LN invoice, Boltz locks BTC on-chain, app claims via Taproot script-path
- **Submarine swaps** (on-chain -> Lightning): App sends BTC on-chain to Boltz, Boltz pays the LN invoice
